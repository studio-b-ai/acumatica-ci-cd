## Objective 3 — Task 2.3 (~variable; this is a multi-session arc)

This is bigger than one session. Goal of this session: **brainstorm + decide architecture, then ship the first piece.**

### 3a. Brainstorm the identity choice

Use `superpowers:brainstorming` to walk Kevin through the decision tree. Inputs to lay out:

| Option | Pros | Cons | Cost |
|---|---|---|---|
| **Service-account GitHub user** (e.g. `studiob-bot`) | Familiar pattern; PAT is scoped per repo via fine-grained PAT | Costs a paid GH seat (~$4/mo); PAT still rotates and expires | $4/mo + rotation maintenance |
| **GitHub App** (e.g. `Studio B Automation`) | No expiry; per-installation scoping; cleanest audit logs; can be installed per-repo | Setup is heavier (manifest, private key, JWT auth in scripts); private key handling is its own security surface | Free; one-time setup cost |
| **Hybrid** | Use existing Anthropic Claude Code action's built-in token exchange where applicable, GitHub App for the rest | Limits the surface area | Same as GitHub App |

The KB says "service-account / GitHub App identity" — both are accepted. The tiebreaker is operational cost: how often will you need to rotate, how many repos need access, do you mind paying $4/mo for clarity.

**Recommended starting point for the brainstorm:** GitHub App, scoped to the studio-b-ai org with read+contents+actions permissions only. Reasons: no expiry, no seat cost, cleanest audit trail (audit logs show `studio-b-bot[bot]`, not a human name), and the Anthropic claude-code-action already supports GitHub App auth out of the box.
